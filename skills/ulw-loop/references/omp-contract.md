# OMP compatibility contract (authoritative)

This is an OMP port of omo 5.1.19, with native task/tool schemas and goal-mode guidance reconciled for omp 18.12.1. The workflow activates only on an explicit request for its named mode (or an explicit request to perform that specialised workflow); bare ULW does not activate planning, looping, execution, saturation research, or mass orchestration. Host and current user instructions outrank this skill. The native behavioural doctrine remains below; this contract replaces harness-specific machinery.

## Native delegation and orchestration

Read the current task schema before dispatch. Supply shared goal and interface constraints in top-level context, and independent assignments in tasks. Include the concise intent field when the exposed schema requires it; eval tool proxies may supply that field. Each entry requires task (the self-contained assignment) and solutionSpace (how fixed or open the solution is, not file scope or workload size). Put exact read/write paths, non-goals, prescribed steps and observable acceptance in task, with TASK / DELIVERABLE / SCOPE / VERIFY / STOP WHEN or the equivalent # Target / # Change / # Acceptance sections. Do not repeat shared context or sibling coordination in solutionSpace. Large shared material belongs in a local:// artifact referenced by literal path, not pasted into every child.

name is optional; when supplied use a unique CamelCase name of at most 32 characters. Omit agent for the default task worker; never send agent: "task". Select only listed specialists: scout for exploratory read-only discovery, sonic for already-decided mechanical work, senior-task for difficult implementation/investigation when available, reviewer or security-reviewer for reviews that accept their native response format, and seance only for read-only historical consultation. For a workflow-specific JSON receipt, omit agent and specify the read-only review charter in task; task text cannot override a specialist's fixed output contract. Difficulty and specialty labels such as quick, deep or architect are planning metadata to map to these roles, never callable agent names or task fields. OMP owns ordinary role model/fallback routing: do not send model, category, subagent_type, prompt or run_in_background for ordinary workers. The exposed seance fields are the exception: pass sourceSession and optional model only with agent: "seance", when the current task schema advertises them and the user or task requires a historical consultation. Record the requested tier and selected role before dispatch, then the resolvedModel/identity/thinking reported by the actual result; never record a planned model as the one that ran. If a required model cannot be selected through the exposed contract, report that capability gap rather than inventing a pin.

The current task entries expose task, solutionSpace, name and agent, plus tools when eval-defined tools are available. A bundled seance task may additionally expose sourceSession and model; effort, isolated and structured fields are conditional on the advertised schema. Do not pass outputSchema or schemaMode unless the current schema explicitly adds them. tools names eval-defined tools; it is not an arbitrary built-in tool allowlist. Respect the host's mid-flight check policy: read covering tests and capture the required reproduction first, then run final build/lint/tests once when the change is ready, not repeatedly during unrelated steps. Completion still requires the assigned checks and independently verified evidence. Children start blank; put every task-specific fact and required skill path in the assignment.

Communicate by write to agent://<actual-agent-id> with content; never invent an id, team, or recipient. Read agent://<id> for one needed midpoint decision; wait collects terminal outputs. No team API is available: a cooperating roster is native background children with the lead relaying discoveries and owning durable shared state. Serialize conflicting writes or use separately owned worktrees. To cancel, read the actual runtime cancellation contract; do not invent a cancellation method, use elapsed time as a reason, or abandon a pending handle.

For a DAG, first read xd://eval/agents if available and use only the documented native workpool surface. If unavailable, use explicit dependency waves through task/wait; no workflow SDK is needed. See ../../mass-ulw/SKILL.md from a references directory (or ../mass-ulw/SKILL.md from a skill root). Completed outputs remain durable and verified; failed nodes block only descendants, unrelated branches continue. Retry the failed node with its exact failure, retain unchanged completed nodes, invalidate changed nodes and their transitive dependents, and record every attempt.

## Background results and recovery

Async bash retains its deadline (300 seconds by default). Use `async: true, timeout: 0` for condition watches and an explicit task-appropriate timeout for finite commands. Long-lived services instead use a unique `name` and `ready`, without `async` or `timeout`; follow the exposed service contract. A steered readiness wait can return while the service is still starting (`ready: false`); read `proc://<name>` before depending on it, because a returned call is not proof of readiness.

Task returns actual child ids immediately. Record a pending set and work independently. Native wait({}) is a wake on the first settled result, message or steering interrupt, not a whole-wave barrier and not a function accepting child handles. Reconcile every returned job and auto-delivered result with its actual id; remove only terminal children, record failures/cancellation, and keep unfinished siblings pending. A message or still-running snapshot is not completion. Wait again only when the next action is blocked on pending work. A downstream node starts only after every dependency has terminal success and independently verified evidence; final delivery requires an empty pending set. The eval helper wait(handles) is a separate documented wave-barrier API, not the native wait tool.

Record actual returned identity and terminal status, without inventing absent metadata. Put required receipt fields or a JSON schema in the task text and validate the actual terminal response from task/wait or agent://<actual-id>. Use structured.data and parsed field selectors only when actually returned by the runtime; a preview, message or running snapshot is not completion. Missing or invalid required fields fail the output contract. Freeform reports may request the following JSON shape, with all headings, citations and EXPAND tails inside report.

```json
{"type":"object","properties":{"report":{"type":"string"}},"required":["report"],"additionalProperties":false}
```

Recovery is lead-owned state plus native actions, not workflow retry/amend/send APIs. For a failed terminal node, retain verified siblings, record the failure and attempt, then spawn a fresh task with failure context and bind its new actual id to the same logical node. A changed definition invalidates that node and its descendants; preserve unchanged verified nodes. Steer a live or idle child through supported agent:// messaging, or a documented AgentHandle.send; a successful send is not a new completion receipt. Reconcile the resulting run before accepting its next result. Do not duplicate live writers; cancel only through the documented native route and collect its terminal state before replacement. Use workpool only through the methods documented in xd://eval/agents; it does not provide graph retry/amend operations.

## Planning choices and authorization channels

Use native blocking ask from the main session for material planning choices and explicit plan-creation decisions after independent work is finished; use only its exposed parameters. Follow host instructions requiring direct permission requests. A timed-out, dismissed, empty or unavailable answer never grants approval or authorizes an irreversible, destructive or spend action, even when a tool suggests proceeding on best judgment. Default only reversible ordinary forks. At a planning approval gate keep `status: awaiting-approval`, write no plan and stop; if ask is unavailable, state that once and await an explicit decision in chat. An explicit no-plan ulw-execute bootstrap already authorizes generating its prerequisite plan, so do not add another generic approval gate there.

## Durable binding goal and evidence

OMP supports native goal mode. This extension routes bare `ulw`/`ultrawork` through `/goal` and observes `goal_updated`; `/ulw` is only an activation alias because OMP's `sendUserMessage()` disables slash-command expansion. Do not invent a goal SDK or tool call. Use direct `ulw` or explicit `/goal` when native goal creation is required. Native goal mode owns that continuation and does not require a second durable ledger for LIGHT work. Explicit `ulw-loop` and `ulw-execute` retain their existing multi-goal/plan files and extension-owned continuation without creating a duplicate native goal. For those durable workflows, record the binding objective, criteria, constraints and WHEN TO STOP through read/write/edit before execution. The lead is the single writer of goal/criteria/ledger state; workers return evidence and cannot safely append concurrently. Read existing state first, preserve its bytes, append ledger entries via edit (or read + write with single ownership), observe the result and read back. No hidden locks, atomic compare-and-swap service or env session binding is assumed. Resume from existing state and actual agent handles after compaction; do not recreate completed work.

Use OMP todo for every registered action and cleanup resource, updating transitions immediately using its actual schema. With parallel children, the lead's current orchestration step can be the single in-progress todo while per-lane states are durable; do not misreport parallel work as completed. Missing artifacts, inconclusive verdicts, or stale proofs block completion.

Bind evidence to tracked tree AND working diff/untracked inputs: HEAD tree alone does not prove uncommitted edits. Record the capture revision, working-content digest or diff, invocation, result, nonempty artifact paths, adversarial cases and cleanup. A changed captured input invalidates dependent proofs; a metadata-only rebase retaining identical content does not. Never relabel old evidence to a new tree.

## Host permissions and real surfaces

Planning approval authorizes plan creation only, never implementation. Explicit execution activation authorizes implementation; no commit is authorized unless the user asked for commits. Inspect history and stage only owned files once commits are authorized; otherwise record no-commit: user has not authorized commits. Worktrees/landing do not bypass this: do not commit, merge, push, open a PR, send external messages, deploy, delete user work, or rewrite history without the applicable explicit user authorization. --make-pr and --ship carry only the explicit scope the user gave; resolve any missing commit/merge authorization at the last gated step after local deliverables and evidence are ready. Preserve dirty user changes. Unrelated defects are local findings, not automatically published issues.

Follow the exposed browser tool contract before real-surface QA; read skill://cua-driver when using its browser or desktop route. Use actual session browser/GUI tools, never unshipped browser engines, a copied login profile, fictional script/qa paths or nonexistent skill names. HTTP uses the live endpoint; CLI/data uses real stdout/state; visual TUI proof needs a real rendered terminal, not capture-pane for colour/layout/CJK. If that renderer is absent, record a capability blocker rather than fake evidence. Browser/page QA includes desktop/mobile, paginated output includes EVERY rendered page. Only tear down task-owned resources, with receipts. Start long commands and condition watches with native async bash; results auto-deliver, and native wait() with no arguments is only for a pending job you started when the next step is blocked. No sleeping or status-poll loops.

Ask is blocking in OMP. Research collection must start before any unresolved format interview; state destination-derived defaults with a visible veto and continue independent collection, then ask a genuinely blocking question only after independent work is done. Do not pass waitForAnswer:false or invent asynchronous question tools. recall/retain are the available memory interface: recall qualified preference episodes, retain observed/declared episodes with provenance; paths named by the original memory doctrine are logical topics, not required filesystem or memory APIs.
