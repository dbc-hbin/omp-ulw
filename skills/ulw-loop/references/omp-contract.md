# OMP compatibility contract (authoritative)

This is an OMP port of omo 5.1.19. The workflow activates only on an explicit request for its named mode (or an explicit request to perform that specialised workflow); bare ULW does not activate planning, looping, execution, saturation research, or mass orchestration. Host and current user instructions outrank this skill. The native behavioural doctrine remains below; this contract replaces harness-specific machinery.

## Native delegation and orchestration

Read the current task schema before dispatch. Supply shared goal and interface constraints in top-level context, and independent assignments in tasks. Include the concise intent field when the exposed schema requires it; eval tool proxies may supply that field. Each entry requires task (the self-contained assignment) and solutionSpace (how fixed or open the solution is, not file scope or workload size). Put exact read/write paths, non-goals, prescribed steps and observable acceptance in task, with TASK / DELIVERABLE / SCOPE / VERIFY / STOP WHEN or the equivalent # Target / # Change / # Acceptance sections. Do not repeat shared context or sibling coordination in solutionSpace. Large shared material belongs in a local:// artifact referenced by literal path, not pasted into every child.

name is optional; when supplied use a unique CamelCase name of at most 32 characters. Omit agent for the default task worker; never send agent: "task". Select only listed specialists: scout for exploratory read-only discovery, sonic for already-decided mechanical work, senior-task for difficult implementation/investigation when available, reviewer or security-reviewer for their corresponding reviews. Difficulty and specialty labels such as quick, deep or architect are planning metadata to map to these roles, never callable agent names or task fields. OMP owns each role's model/fallback routing: do not send model, category, subagent_type, prompt or run_in_background. Record the requested tier and selected role before dispatch, then the resolvedModel/identity/thinking reported by the actual result; never record a planned model as the one that ran. If a required model cannot be selected through the exposed contract, report that capability gap rather than inventing a pin.

Optional task fields are outputSchema, schemaMode and tools only as exposed by the current schema. tools names eval-defined tools; it is not an arbitrary built-in tool allowlist. Respect the host's mid-flight check policy: read covering tests and capture the required reproduction first, then run final build/lint/tests once when the change is ready, not repeatedly during unrelated steps. Completion still requires the assigned checks and independently verified evidence. Children start blank; put every task-specific fact and required skill path in the assignment.

Communicate by write to agent://<actual-agent-id> with content; never invent an id, team, or recipient. Read agent://<id> for one needed midpoint decision; wait collects terminal outputs. No team API is available: a cooperating roster is native background children with the lead relaying discoveries and owning durable shared state. Serialize conflicting writes or use separately owned worktrees. To cancel, read the actual runtime cancellation contract; do not invent a cancellation method, use elapsed time as a reason, or abandon a pending handle.

For a DAG, first read xd://eval/agents if available and use only the documented native workpool surface. If unavailable, use explicit dependency waves through task/wait; no workflow SDK is needed. See ../../mass-ulw/SKILL.md from a references directory (or ../mass-ulw/SKILL.md from a skill root). Completed outputs remain durable and verified; failed nodes block only descendants, unrelated branches continue. Retry the failed node with its exact failure, retain unchanged completed nodes, invalidate changed nodes and their transitive dependents, and record every attempt.

## Background results and recovery

Task returns actual child ids immediately. Record a pending set and work independently. Native wait({}) is a wake on the first settled result, message or steering interrupt, not a whole-wave barrier and not a function accepting child handles. Reconcile every returned job and auto-delivered result with its actual id; remove only terminal children, record failures/cancellation, and keep unfinished siblings pending. A message or still-running snapshot is not completion. Wait again only when the next action is blocked on pending work. A downstream node starts only after every dependency has terminal success and independently verified evidence; final delivery requires an empty pending set. The eval helper wait(handles) is a separate documented wave-barrier API, not the native wait tool.

Record each result's actual resolvedModel/identity/thinking and structured status. When structured.status is valid, consume structured.data or the validated payload at agent://<actual-id>; field selectors such as /report expose the parsed field. Do not treat resultText, the task-result wrapper, or a preview as the payload. When a workflow requires a specific result shape, pass outputSchema and schemaMode: "strict" to override the role/session default; instructions alone do not override scout or sonic's output schema. A missing/invalid required payload is a failed output contract, never evidence of completion. Freeform research/planning reports use the following outputSchema and return all headings, citations and EXPAND tails inside report. Read agent://<actual-id>/report or extract structured.data.report before journaling, parsing leads or comparing text. For DoneClaim and AdversarialVerify, instead provide an object schema matching that workflow's required keys and verdict values.

```json
{"type":"object","properties":{"report":{"type":"string"}},"required":["report"],"additionalProperties":false}
```

Recovery is lead-owned state plus native actions, not workflow retry/amend/send APIs. For a failed terminal node, retain verified siblings, record the failure and attempt, then spawn a fresh task with failure context and bind its new actual id to the same logical node. A changed definition invalidates that node and its descendants; preserve unchanged verified nodes. Steer a live or idle child through supported agent:// messaging, or a documented AgentHandle.send; a successful send is not a new completion receipt. Reconcile the resulting run before accepting its next result. Do not duplicate live writers; cancel only through the documented native route and collect its terminal state before replacement. Use workpool only through the methods documented in xd://eval/agents; it does not provide Senpi graph retry/amend operations.

## Planning choices and authorization channels

Use native blocking ask from the main session for material planning choices and explicit plan-creation decisions after independent work is finished; no wait flag or Senpi question tool is needed. Follow host instructions requiring direct permission requests. A timed-out, dismissed, empty or unavailable answer never grants approval or authorizes an irreversible, destructive or spend action, even when a tool suggests proceeding on best judgment. Default only reversible ordinary forks. At a planning approval gate keep `status: awaiting-approval`, write no plan and stop; if ask is unavailable, state that once and await an explicit decision in chat. An explicit no-plan ulw-execute bootstrap already authorizes generating its prerequisite plan, so do not add another generic approval gate there.

## Durable binding goal and evidence

OMP has no goal SDK or goal tool. Record the binding objective, criteria, constraints and WHEN TO STOP in durable files through read/write/edit before execution. This is the canonical no-goal-tool fallback, not an optional notepad substitute. The lead is the single writer of goal/criteria/ledger state; workers return evidence and cannot safely append concurrently. Read existing state first, preserve its bytes, append ledger entries via edit (or read + write with single ownership), observe the result and read back. No hidden locks, atomic compare-and-swap service, env session binding, or automatic continuation is assumed. Resume from files and actual agent handles after compaction; do not recreate completed work.

Use OMP todo for every registered action and cleanup resource, updating transitions immediately using its actual schema. With parallel children, the lead's current orchestration step can be the single in-progress todo while per-lane states are durable; do not misreport parallel work as completed. Missing artifacts, inconclusive verdicts, or stale proofs block completion.

Bind evidence to tracked tree AND working diff/untracked inputs: HEAD tree alone does not prove uncommitted edits. Record the capture revision, working-content digest or diff, invocation, result, nonempty artifact paths, adversarial cases and cleanup. A changed captured input invalidates dependent proofs; a metadata-only rebase retaining identical content does not. Never relabel old evidence to a new tree.

## Host permissions and real surfaces

Planning approval authorizes plan creation only, never implementation. Explicit execution activation authorizes implementation; no commit is authorized unless the user asked for commits. Inspect history and stage only owned files once commits are authorized; otherwise record no-commit: user has not authorized commits. Worktrees/landing do not bypass this: do not commit, merge, push, open a PR, send external messages, deploy, delete user work, or rewrite history without the applicable explicit user authorization. --make-pr and --ship carry only the explicit scope the user gave; resolve any missing commit/merge authorization at the last gated step after local deliverables and evidence are ready. Preserve dirty user changes. Unrelated defects are local findings, not automatically published issues.

Read matching installed browser/computer-use skills before real-surface QA (ego-browser and cua-driver on this host). Use actual session browser/GUI tools, never unshipped omowright/browser engines, a copied login profile, fictional script/qa paths or nonexistent skill names. HTTP uses the live endpoint; CLI/data uses real stdout/state; visual TUI proof needs a real rendered terminal, not capture-pane for colour/layout/CJK. If that renderer is absent, record a capability blocker rather than fake evidence. Browser/page QA includes desktop/mobile, paginated output includes EVERY rendered page. Only tear down task-owned resources, with receipts. Start long commands and condition watches with native async bash and collect their handles through wait; no sleeping or status-poll loops.

Ask is blocking in OMP. Research collection must start before any unresolved format interview; state destination-derived defaults with a visible veto and continue independent collection, then ask a genuinely blocking question only after independent work is done. Do not pass waitForAnswer:false or invent asynchronous question tools. recall/retain are the available memory interface: recall qualified preference episodes, retain observed/declared episodes with provenance; paths named by the original memory doctrine are logical topics, not required filesystem or memory APIs.
