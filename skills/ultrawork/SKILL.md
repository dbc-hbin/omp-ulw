# ULW scope

On explicit activation, include `ULTRAWORK MODE ENABLED!` after any host-required opening. Reading or discussing this skill does not request its execution. ULW activation persists for the session; a follow-up does not restart a workflow.

OMP owns execution: its current system instructions, tool contracts and native modes govern decomposition, delegation, model choice, tools, waiting, verification, permissions and reporting. ULW adds no competing orchestration or QA procedure. The extension connects explicit specialised invocations to native keywords: planning uses `ultrathink`, execution/loop uses `orchestrate`, and research/mass uses `workflowz`. A user-supplied native keyword takes precedence over that default. OMP owns the resulting notice, settings/tool gates and thinking effort; do not inject another copy or replay the trigger on follow-ups. Plain ULW selects no specialised native mode, and `jevify` remains an explicit choice.

## Goal ownership

For plain ULW, use the OMP-native goal already created by the interactive `/ulw` or `ulw`/`ultrawork` input route. An active goal is preserved. RPC and programmatic activation alone do not create a goal; the client must use OMP's native goal API. Do not infer goal creation from this policy or create a second ULW goal, notepad or ledger for an ordinary task.

Explicit durable workflows keep their own state instead of adding a competing native goal:

- `ulw-plan`: a decision-complete plan, without product implementation.
- `ulw-execute`: a selected plan, Boulder ownership and task/evidence ledger.
- `ulw-loop`: multiple goals, dependencies and verified checkpoints.
- `mass-ulw`: a dependency graph and node recovery records; use an owning loop or execution goal when present.
- `ulw-research`: research claims, source evidence and a cited deliverable.

Read a specialised skill only when that workflow is requested or its specific artifact contract is needed. Bare ULW does not select any of them. The selected workflow owns its artifacts; OMP owns how the work is performed. Resume existing state rather than creating another record of the same objective. Child assignments do not inherit ULW activation or ownership of the parent workflow.
